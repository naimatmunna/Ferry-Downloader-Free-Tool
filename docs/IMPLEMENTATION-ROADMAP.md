## Testing strategy

| Layer | Tooling | What is covered |
|---|---|---|
| Unit | `node --test` | URL detection & normalization, platform routing, catalog integrity, policy resolution, format compatibility & planner, capability checks, filename templates & sanitization, content-disposition, job state transitions, IP classification, rate limiter, error classification of engine output, progress parsing. |
| Integration | `node --test` + real binaries | API endpoints on an ephemeral port; queue processing; yt-dlp generic extractor and direct adapter against a **local fixture server** serving media generated by FFmpeg (`testsrc2` + `sine`, i.e. media we created ourselves); FFmpeg conversions for every container/format; file delivery with Range; ZIP; cleanup sweeper; egress proxy blocking. |
| End-to-end | Playwright (system Edge/Chrome channel) | Paste → detect → preview → video+audio / video-only / audio-only → complete download → retry a failed job → mobile viewport flow. |
| Live smoke (opt-in) | `FERRY_LIVE_TESTS=1` | Permitted public sources only (public-domain items on Internet Archive, CC media on Wikimedia Commons, a PeerTube video with downloads enabled). |
| Performance | scripts in `scripts/perf/` | Bundle size, detection latency, probe latency (fixtures), worker throughput, RSS while streaming a 1 GB file, CPU during transcodes. |

Only media we generated ourselves or media whose license permits downloading is
used in tests.

## Post-MVP roadmap

1. **Scale-out drivers** — BullMQ/Redis job queue + store, S3-compatible output storage with presigned URLs, MongoDB policy/audit store.
2. **gallery-dl adapter** — image galleries and carousels (license review: GPL-2.0, subprocess use).
3. **Streamlink adapter** — authorized livestream recording with duration caps.
4. **Official export integrations** — OAuth flows that use platform-provided download features for a user's *own* content.
5. **Aspect-ratio tools** — crop/pad presets for social formats.
6. **Accounts (optional)** — end-to-end encrypted history sync.
7. **More languages** and community translations.

### Known limitations (honest list)

* Single-node only: `ROLE=api|worker` split needs the BullMQ/Redis + S3 drivers (designed, not implemented).
* Image galleries (gallery-dl) and livestream recording (Streamlink) are listed in the registry as
  "not on this server yet" until those adapters exist.
* Live third-party sites were not exercised by the automated suites (fixtures only), so per-platform
  reliability comes from upstream engine status and will be refined by the live status page.
* yt-dlp probes take 2–4 s on this Windows machine (Python start-up); direct and official-API probes ~0.1 s.
